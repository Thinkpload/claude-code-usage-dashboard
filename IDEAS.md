# Идеи

Бэклог улучшений. Каждая идея привязана к реальной проблеме; при переносе в скилл действует правило
близнецов из CLAUDE.md (логика, тесты, шаблон — в обе копии).

### I1. Веса и подписи моделей: сливать с умолчаниями, а не заменять
`load_config()` сливает конфиг поверхностно: если в `config.json` есть `token_weights` или
`model_labels`, умолчания из `DEFAULT_CONFIG` для этих ключей пропадают целиком. Новая модель,
добавленная в код (как `claude-opus-5-5`), до существующих пользователей не доходит — её надо
вписывать руками. Сливать эти два словаря по ключам: умолчания + переопределения пользователя.
**Почему:** 28.09.2026 Opus 5.5 считался по весам Opus 5 и завышал расход; пришлось править и код, и
личный `config.json`.

### I2. Предупреждать о модели без своих весов
Модель, попавшая в веса только по префиксу (`claude-opus-5-5` → `claude-opus`) или по `default`,
считается молча. Печатать в выводе запуска и показывать значком на дашборде: «claude-opus-5-5
взвешен как claude-opus — проверь цены». Так же для модели без подписи в `model_labels`.
**Связано:** I1 закрывает большую часть случаев, I2 — сигнал на остальные.
**Почему:** та же история с Opus 5.5 — ошибка в ~25 % по модели была незаметна.

### I3. Сигнал «лимит изменился»
Сейчас неделя со своим показанием `/usage` идёт по нему, но общий бюджет (для недель без показаний и
для подписи «бюджет восстановлен по N показаниям») смешивает режимы. Сравнивать бюджет текущей
недели с общим и при расхождении больше ~30 % писать на приборе: «лимит этой недели ×2,3 к
прежним — акция или новая модель?», с подсказкой завести `boosts`. Возможно, считать общий бюджет
только по последним 2–3 неделям.
**Почему:** после 24.09.2026 бюджет вырос с ~700 до ~1600 единиц без объявления, дашборд показывал
44 % при реальных 21 %.
**Напряжение:** «из последних недель» быстрее ловит смену режима, но шумнее на ранних показаниях
(1–3 %, округлённых до целого) — ради которых и сделано объединение по размеру.

### I4. История облачного кредита и что его тратит
Хранить снимок кредита при каждом запуске (не только последний) и показывать дневной прирост. Для
разбивки — сопоставлять прирост с запусками рутин (`/v1/code/triggers` + их сессии, тот же токен
входа).
**Почему:** на вопрос «на что ушли $1,38» ответить нечем — `/usage` отдаёт только сумму.
**Напряжение:** эндпоинты рутин, как и `/usage`, недокументированы; кредит лежит под кодовым именем
(`iguana_necktie`). Больше хрупких зависимостей — больше тихих поломок.

### I5. Разбивка недели по поверхностям из `seven_day_breakdown`
Ответ `/usage` уже содержит доли недели: Claude Code / чаты / Cowork / прочее. Сохранять и
показывать рядом с полосой недели — это и объясняет, почему прибор по журналам идёт ниже `/usage`
(чаты и рутины журналы не видят).
**Связано:** README → Caveats, пункт про расхождение с `/usage` — сейчас это только текст.

### I6. Видно, что дашборд устарел, и пропущенный запуск догоняется
Если данные старше ~26 ч, помечать шапку («собрано 2 дня назад — ночной запуск не прошёл»). В
документации к планировщику — «запускать при первой возможности, если пропущено» и повтор при сбое.
**Почему:** запуск 27.09.2026 был прерван (0xC000013A), дашборд полтора дня показывал 26.09 без
всякого знака.
