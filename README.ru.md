# Счётчик Claude Code

[![PyPI](https://img.shields.io/pypi/v/claude-usage-dashboard)](https://pypi.org/project/claude-usage-dashboard/)
[![CI](https://github.com/Thinkpload/claude-code-usage-dashboard/actions/workflows/ci.yml/badge.svg)](https://github.com/Thinkpload/claude-code-usage-dashboard/actions/workflows/ci.yml)
[![License](https://img.shields.io/badge/license-MIT-blue)](LICENSE)

Одна самодостаточная HTML-страница, отвечающая на то, о чём молчит `/usage`: куда ушли часы в
Claude Code, какие проекты их съели и выйдет ли текущий темп ровно в недельный лимит или оставит
половину неиспользованной.

Читает журналы сессий, которые Claude Code и так пишет в `~/.claude/projects/**/*.jsonl`. Без
учётной записи, без ключа API, без сети. Чистый Python, никаких зависимостей.

## Что показывает

- **Во что на самом деле обходится уровень усилия?** Anthropic этого не публикует. Дашборд считает
  это по вашим журналам, от `low` до `max`: один вызов на каждом уровне против вызова на `high` на той
  же версии модели и при похожем размере контекста — ни модель подороже, ни контекст подлиннее не
  выдают себя за усилие. И цена в лимите, и вывод с размышлениями, по всем моделям или по каждой.
  На одном реальном месяце: `max` — ×1,59 по цене и ×1,91 по выводу против `high`, `medium` — ×0,86;
  на одном Fable 5.1 `xhigh` стоит ×1,56 от `high`, а по всем моделям — ×1,14.
- **Упрусь ли я в недельный лимит?** Откалиброванный прибор, а не догадка: `k = факт ÷ план`, где
  план считается по тому, *когда я обычно работаю*, а не по календарю. Формулировки вида «упрёшься
  в лимит в среду около 11:00 и до сброса будешь обходиться без него 1 д 8 ч». Риски на полосе недели
  отсчитывают 5-часовые окна, которые ещё влезают до сброса; у кредита на облачные сессии своя полоса.
- **Подходит ли мой тариф?** Оплаченный месяц по неделям: каждая лимитная неделя против своего лимита,
  как она поднималась час за часом, что сгорело неиспользованным, и вывод — тариф в самый раз, с
  запасом или упирается в потолок, и тариф побольше окупится.
- **Куда ушло время?** Активные часы по проектам, три группы (основная работа / рабочее окружение /
  личное), по дням, по месяцам и тепловой картой день недели × час.
- **Из чего состоит расход?** Токены по моделям, по размеру контекста, по уровню усилия, по тексту
  навыков в контексте, по субагентам, по холодным стартам сессий — и к каждому пункту совет.
- **Что из этого доехало?** Коммиты из локальных репозиториев на той же оси времени.

## Быстрый старт

Ничего не устанавливая и не клонируя:

```bash
uvx claude-usage-dashboard --open
```

`pipx run claude-usage-dashboard --open` делает то же самое, а `pip install claude-usage-dashboard`
оставит команду насовсем. Или забрать себе и запускать на месте:

```bash
git clone https://github.com/Thinkpload/claude-code-usage-dashboard
cd claude-code-usage-dashboard
python -m claude_usage_dashboard --open
```

И так и так: просканирует журналы, запишет `~/.claude/usage-report/` и откроет страницу. Скан сотни
сессий занимает до минуты, дальше всё мгновенно. Нужны свежие цифры — запустите снова: страница
обычный файл, ни сервера, ни демона.

В Windows один запуск с `--register-refresh` добавляет на страницу кнопку **обновить**: она открывает
ссылку `claude-usage://`, которая пересканирует журналы в фоне, а страница перезагрузится, когда
будет готова новая сборка (в первый раз браузер спросит разрешения). Регистрировать из `pip install`
или клона — копия `uvx`/`pipx run` живёт во временном окружении, которое ссылка переживёт.

Python 3.9+, только стандартная библиотека. Windows, macOS и Linux.

## Сделать шкалу лимита настоящей

Anthropic не публикует лимиты в токенах, поэтому любой инструмент, уверенно называющий остаток
квоты, гадает. Этот вместо гадания калибруется по настоящей цифре `/usage`.

При каждом запуске он берёт её тем же способом, что и панель `/usage` в Claude Code: токеном входа
из `~/.claude/.credentials.json`, который уходит на `api.anthropic.com` и больше никуда. Токен не
печатается и никуда не копируется. Записываются процент недели по «всем моделям», процент Fable,
момент сброса недели, 5-часовое окно с его сбросом и кредит на облачные сессии, если он есть.
Повторный запуск в течение часа заменяет последнее показание, а не добавляет новое.

Если не хотите, чтобы инструмент трогал токен, запускайте с `--no-fetch` и заносите показание сами
из **claude.ai → Settings → Usage** (или `/usage` в Claude Code):

```bash
claude-usage-dashboard --observe 46 --fable 31 --reset "2026-09-17 20:00"
```

- `--observe` — процент недели по «всем моделям»
- `--fable` — процент Fable, у него отдельный бюджет
- `--reset` — момент сброса недели

По каждому показанию скрипт восстанавливает недельный бюджет вашего тарифа в *единицах нагрузки*
(токены с весами по модели и типу) и дальше ведёт каждую следующую неделю сам. Показания
объединяются по размеру: 1 % в первый день недели не заглушит 48 % с пятого. Неделя со своим
показанием идёт по последнему из них, так что необъявленная смена лимита (акция, новая модель) не
уведёт прибор от того, что показывает `/usage`. Пока показаний нет,
прибор так и говорит, а не выдумывает цифру.

Веса — цены API, а лимит берёт за модели не совсем так, как прайс: на единицу Fable грузит его
сильнее, чем говорит его цена относительно Opus (на одном реальном месяце — примерно вдвое). Поэтому
вес единицы Fable тоже подбирается по вашим показаниям, и каждая неделя считается с ним. Без этого
неделя, шедшая на Fable до последнего показания и на Opus после него, показала 101 % лимита, в который
никто не упирался. Вес остаётся по цене API, пока хотя бы восемь показаний уверенно не сойдутся на
другом, — так округление до целого процента его не выдумает. 5-часовое окно меряется по своим
показаниям так же и рисуется рисками на полосе недели.

Тарифы калибруются раздельно: показание на Max никогда не пересчитывается в бюджет Pro, потому что
«Pro = Max ÷ 5» проверено на реальных неделях и не сходится.

## Как считает

| | |
|---|---|
| **Источник** | `~/.claude/projects/**/*.jsonl` — журналы, которые Claude Code пишет и так |
| **Один вызов** | один `requestId`: вызов API размазан по нескольким строкам журнала, дубликаты схлопываются |
| **Активное время** | сумма промежутков между соседними записями не длиннее `idle_minutes` (по умолчанию 10), так что открытое на ночь окно ничего не стоит |
| **История** | дневные срезы копятся в `history.json`, поэтому дни, которые Claude Code стирает через 30 дней, остаются |
| **Тренд** | на виде «30 дней» у каждого показателя стрелка неделя к неделе: последние 7 дней против предыдущих 7; доля работы — в пунктах, остальное — в процентах |
| **Единицы нагрузки** | токены × веса по моделям (прайс API строго как веса) — валюта, на которой говорит шкала лимита |
| **Оплаченный месяц** | идёт с того дня, когда начался текущий тариф; каждая лимитная неделя даёт ему бюджет пропорционально дням, которые в нём проводит, так что месяц читается как доля того, что лимит на деле позволял |

Запускать хотя бы раз в месяц или по расписанию, иначе чистка журналов обгонит историю.

## Настройки

Скопируйте `config.example.json` в `~/.claude/usage-report/config.json` и правьте. Что важно:

| Ключ | Зачем |
|---|---|
| `groups` | три группы проектов по маскам имён, первая подошедшая побеждает — это и есть смысл цветов |
| `plan_history` | какой тариф действовал когда: `[{"from": "2026-09-08", "plan": "max5"}]`; день последней записи — ещё и день, с которого идёт оплаченный месяц |
| `observations` | ваши показания `/usage`; подтягиваются при каждом запуске (или пишутся флагом `--observe`), можно править руками |
| `week_reset` | момент сброса недели из `/usage` |
| `boosts` | временные акции: `[{"from": …, "to": …, "factor": 1.5}]` |
| `git_roots`, `git_authors` | где лежат репозитории и какие маски автора считать вами |
| `idle_minutes` | промежуток, после которого время перестаёт быть активным |
| `lang` | `en` или `ru` |

`--out-dir DIR` уводит всю работу в другую папку данных — так собирается демо, не задевая ваши файлы.

## Как навык Claude Code

Скопируйте или слинкуйте репозиторий в `~/.claude/skills/claude-usage-report/` — `SKILL.md` лежит в
корне, так что папка работает навыком как есть. Дальше можно спрашивать «сколько я потратил за
месяц» или «обнови дашборд использования»: Claude Code запустит скрипт, назовёт цифры и опубликует
страницу артефактом.

## Свой облик

Страница — один HTML-файл без внешних скриптов: открывается из `file://` и одинаково хорошо живёт
артефактом на claude.ai. Механика и облик разделены намеренно: все цвета и шрифты — в блоке `:root`
в начале `claude_usage_dashboard/template.html`, а `<div class="bg">` оставлен пустым под любой фон.
Есть и светлая тема — в один щелчок на самой странице:

![Светлая тема](docs/screenshot-light.ru.png)

- Отдайте `dashboard.design.html` (та же страница на маленькой выборке) дизайн-модели, потом
  `python -m claude_usage_dashboard --adopt результат.html` вернёт новый облик в шаблон, сохранив крючки
  данных. Старый шаблон ляжет рядом как `template.bak.html`.
- Или не трогайте страницу вовсе и соберите свою поверх `data.json` — поля описаны в
  [docs/data-contract.md](docs/data-contract.md).
- `template.html` — английский оригинал, `i18n/ru.json` рядом — плоская карта, собирающая из него русскую
  страницу. Новый язык = ещё один такой файл.

## Чем отличается от ccusage

[ccusage](https://github.com/ryoppippi/ccusage) — известный CLI в этой нише, и своё дело он делает
хорошо: быстрые таблицы стоимости по сессиям и дням прямо в терминале.

Здесь задача другая:

- **страница вместо таблицы** — тепловые карты, тренды, недельный прибор
- **недельный лимит**, откалиброванный по вашим показаниям `/usage`, включая отдельную шкалу Fable
- **история, переживающая** 30-дневную чистку журналов Claude Code
- **группировка проектов** на работу и личное, с коммитами рядом с часами

Они отвечают на разные вопросы, и ничто не мешает держать оба.

## Оговорки

- Всё, что касается недельного лимита, — модель поверх ваших показаний `/usage`, а не опубликованные
  данные. Неоткалиброванные цифры страница помечает как оценку, а не выдаёт за факт.
- Журналы видят только Claude Code на этом компьютере, а `/usage` считает ещё чаты и облачные рутины
  (собственная разбивка эндпоинта показывает долю). Поэтому прибор может стоять на несколько пунктов
  ниже `/usage`, заметнее всего сразу после облачной рутины; ежедневные показания это выравнивают.
- Показание берётся через недокументированный API: это тот же вызов, что делает панель `/usage`, и он
  может измениться. Когда он перестанет работать, запуск так и скажет и продолжит на уже собранных
  показаниях.
- Расход навыков считает только перечитывание их текста из кэша; `/usage` считает шире.
- В отчёте видны имена ваших проектов. Подумайте, прежде чем класть собранную страницу на всеобщее
  обозрение.
