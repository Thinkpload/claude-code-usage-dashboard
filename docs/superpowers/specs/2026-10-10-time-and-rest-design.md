# Твоё время, отдых и ручная работа — дизайн

Дата: 2026-10-10. Статус: согласован в чате, ждёт ревью спека.

Доработка «для удобства»: дашборд показывает, сколько времени ты реально проводишь за Claude за день и
неделю, предупреждает о переработке, живой хук напоминает сделать перерыв, а блок советов подсказывает,
где ручную работу пора автоматизировать. Всё приблизительно и только по журналам сессий.

## Почему текущей цифры мало

«Активное время» (`sec` в `days[d][project]`) суммируется по сессиям, поэтому параллельные сессии считаются
дважды. На реальных журналах за 26.09–10.10.2026 сумма в 1,2–1,7 раза больше, чем время, когда хоть одна
сессия была занята (28.09: 19,2 ч против 11,8 ч). Но и время занятости не годится для отдыха: 08.10 Claude
был занят 21,4 ч — работали агенты и циклы, а не человек. Отсюда две новые метрики:

- **Твоё время** — сколько ты сам провёл за Claude: объединение (по всем сессиям и проектам) отрезков
  между твоими соседними сообщениями, если пауза между ними не больше `break_minutes` (15). Пауза длиннее —
  перерыв. Время чтения ответа после последнего сообщения отрезка не считается — цифра занижена, это
  оговаривается на странице.
- **Claude в работе** — сколько времени была занята хотя бы одна сессия: объединение отрезков между
  соседними записями любой сессии (субагенты включены), паузы не больше `idle_minutes`. Параллельные
  сессии считаются один раз.

Существующие `sec`, `hours` и доли проектов не меняются.

## Что считается твоим сообщением

Запись `type == "user"`, у которой нет `isMeta`, нет `isSidechain`, `entrypoint != "sdk-cli"` (запуски
`claude -p`), содержимое — не `tool_result`, текст не начинается с `<` (служебные теги команд) и не
`[Request interrupted by user`. Отсев проверен на журналах: без него в «повторах» лидируют промпты
субагентов и прерывания.

## 1. Данные (`scan` → `merge` → `history.json`)

**По дню** — новый раздел `history["presence"][d]`:

```
{"you": 25200,      // твоё время, с
 "busy": 41000,     // Claude в работе, с
 "longest": 6300,   // самый длинный отрезок твоего времени без перерыва, с
 "night": 1800}     // твоё время в часы 00–06, с
```

Отрезок, пересекающий полночь, делится по дням (`you`, `busy`, `night`); `longest` записывается целиком
дню, в котором отрезок начался. `merge` оставляет снимок с большим `busy` (тот же принцип «полнее журнал —
полнее снимок», что и для проектов).

**По проекту за день** — три новых поля в `days[d][project]`:

- `mine` — число твоих сообщений (по правилам раздела выше), знаменатель для доли подталкиваний.
- `nudges` — число твоих коротких сообщений-подталкиваний: не длиннее 15 символов после `strip()`, не
  начинаются с `/`.
- `prompts` — `{начало: сколько раз}`: нормализованное начало запроса (нижний регистр, пробелы схлопнуты,
  первые 80 символов) для сообщений от 20 символов и не начинающихся с `/`.

Старые записи истории без этих полей читаются как нули.

## 2. Новые настройки

```
"break_minutes": 15,         // пауза между твоими сообщениями длиннее — перерыв
"remind_after_minutes": 90   // хук напоминает, когда отрезок без перерыва длиннее
```

## 3. Дашборд

**Карточка «Твоё время и отдых»** — первая в `board`, ширина 12, от выбранного периода не зависит
(подпись в шапке карточки):

- сегодня: твоё время, рядом мелко «Claude в работе»;
- эта неделя (пн–вс): твоё время и среднее за 4 предыдущие недели;
- самый длинный отрезок без перерыва — сегодня и за неделю;
- ночные часы за неделю;
- дней подряд без выходного (выходной — день, где твоего времени меньше 30 мин), до сегодня включительно.

Предупреждения на карточке (в стиле существующих советов `warn`/`ok`):

| условие | текст по смыслу |
|---|---|
| сегодня > 8 ч | долгий день, закругляйся |
| неделя > 45 ч | неделя тяжелее обычной рабочей |
| отрезок без перерыва > 2 ч (сегодня или за неделю) | вставай раз в 60–90 мин |
| ночью ≥ 30 мин за неделю | ночная работа, сдвигай на день |
| 7+ дней подряд без выходного | нужен день без Claude |

Если ни одно не сработало — одна строка `ok` «режим в норме».

**Раздел «Ручная работа»** в блоке советов (`k-advice`), считается за выбранный период:

- **Повторяющиеся запросы**: начало запроса, встретившееся 3+ раз в 2+ разных днях. До 5 штук: текст,
  сколько раз, в каких проектах. Совет: вынести в скилл или слэш-команду.
- **Подталкивания**: если доля `nudges` от `mine` ≥ 10 % (и `mine` ≥ 20, чтобы не судить по горстке). Совет: режим auto, план заранее,
  `/fewer-permission-prompts`, `/loop` для повторяющихся проверок.

**Приватность**: текст запросов есть только в локальном `dashboard.html` и `data.json`. В
`dashboard.artifact.html` и `dashboard.design.html` ключи `prompts` заменяются стабильным анонимным
ключом `#` + 8 знаков sha1 — счёт и группировка работают, вместо текста страница пишет «текст скрыт в
опубликованной копии».

Все новые строки шаблона — в `i18n/ru.json`.

## 4. Хук «пора отдохнуть»

Флаг `--break-check` для хука `UserPromptSubmit`. Работает до сканирования журналов и сразу выходит.

Состояние в `<out_dir>/break.json`, общее для всех сессий: `{"start", "last", "nudged"}` (ISO-время).

1. Если с `last` прошло больше `break_minutes` (или файла нет) — `start = now`.
2. `last = now`.
3. Если `now - start ≥ remind_after_minutes` и с `nudged` прошло не меньше 30 мин (или его нет) —
   печатает `{"systemMessage": "You've been at it for 1 h 45 min without a break — stand up for 10 minutes."}`,
   `nudged = now`.
4. Всегда код выхода 0, запрос не блокируется. Ошибка чтения состояния — начать заново, не падать.

Подключение — сниппет для `settings.json` в SKILL.md. В личный `~/.claude/settings.json` хук вносится
только после отдельного согласия.

## 5. Тесты

- объединение интервалов: две параллельные сессии дают `busy` меньше суммы; отрезок через полночь;
- «твоё время»: пауза > `break_minutes` рвёт отрезок; `longest`, `night`;
- отсев: субагенты, `sdk-cli`, прерывания, `tool_result`, теги не считаются сообщениями;
- `nudges` и `prompts`: пороги длины, нормализация, слэш-команды;
- `merge` для `presence`, чтение старой истории без новых полей;
- анонимизация: в artifact/design нет текста запросов, ключи совпадают для одинаковых запросов;
- `--break-check`: новый отрезок, продолжение, напоминание, не чаще раза в 30 мин, битый `break.json`.
